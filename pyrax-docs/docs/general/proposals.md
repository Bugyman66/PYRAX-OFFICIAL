# Creating Proposals

This guide explains how to create governance proposals for the PYRAX DAO.

## Proposal Requirements

### Minimum Threshold
To create a proposal, you need:
- **100,000 PYRAX** (directly held or delegated to you)

Don't have enough? Options:
- Accumulate more PYRAX
- Get delegation from others
- Partner with larger holders
- Submit idea for others to propose

### Proposal Quality
Successful proposals typically have:
- Clear problem statement
- Specific solution
- Measurable outcomes
- Community support

## Proposal Process

### 1. Idea Development
Before formal proposal:
- Discuss in Discord governance channel
- Post on community forum
- Gather initial feedback
- Refine your idea

### 2. Draft Proposal
Write a comprehensive proposal including:
- Title and summary
- Motivation/problem
- Detailed specification
- Expected benefits
- Potential risks
- Implementation timeline

### 3. Community Discussion
- Post draft for feedback
- Respond to questions
- Address concerns
- Build consensus

### 4. Formal Submission
- Submit on-chain via DAO portal
- Pay submission gas fee
- Proposal enters voting queue

### 5. Voting Period
- 7 days for standard proposals
- Community votes For/Against/Abstain
- Quorum must be reached

### 6. Execution
If passed:
- Automatic execution (if possible)
- Or queued for implementation

## Proposal Template

```markdown

## Summary
One paragraph explaining what this proposal does.

## Motivation
### Problem
What issue does this address?

### Current State

### Proposed Change
What should change?

## Specification

### Technical Details
Exact parameters, code changes, or process modifications.

### Implementation Steps

2. Step two
3. Step three

- Benefit 3

- Link to discussion
- Related proposals
- Technical documentation
```

## Proposal Categories

### Parameter Changes
Adjusting existing protocol settings:
- Fee percentages
- Staking rates
- Mining parameters

**Requirements:**
- Specific before/after values
- Justification for change
- Impact analysis

### Treasury Spending
Requesting funds from treasury:
- Grant requests
- Development funding
- Marketing budgets

**Requirements:**
- Detailed budget breakdown
- Milestone schedule
- Accountability measures

### Protocol Upgrades
Major technical changes:
- Smart contract updates
- New features
- Architecture changes

**Requirements:**
- Technical specification
- Security considerations
- Testing/audit plans

### Governance Changes
Modifying DAO rules:
- Voting parameters
- Proposal requirements
- Organizational structure

**Requirements:**
- Strong justification
- Community consensus
- Constitutional process (if major)

## Tips for Success

### Build Support First
- Never surprise the community
- Discuss extensively before proposing
- Address objections proactively
- Line up key supporters

### Be Specific
Vague proposals fail. Include:
- Exact numbers and parameters
- Clear implementation steps
- Defined success metrics
- Specific timeline

### Consider Opposition
- Anticipate counterarguments
- Provide data and evidence
- Show you've considered alternatives
- Be open to compromise

### Communicate Actively
During voting period:
- Answer all questions
- Clarify misunderstandings
- Provide additional information
- Remain professional

### Iterate Based on Feedback
If proposal struggles:
- Listen to concerns
- Consider modifications
- Withdraw and revise if needed
- Resubmit improved version

## Common Proposal Mistakes

### Too Vague
❌ "Improve mining rewards"
✅ "Increase block reward by 5% for 6 months to boost network security"

### No Community Discussion
❌ Surprise proposal with no prior discussion
✅ Weeks of forum discussion before submission

### Unrealistic Scope
❌ "Complete protocol overhaul"
✅ "Specific improvement to X feature"

### Missing Details
❌ "This will cost some money"
✅ "Budget: 50,000 PYRAX over 3 months with monthly milestones"

### Ignoring Feedback
❌ Dismissing valid concerns
✅ Addressing concerns with data and modifications

## After Your Proposal

### If It Passes
- Celebrate! Thank supporters
- Begin implementation
- Provide progress updates
- Complete all milestones

### If It Fails
- Thank participants
- Analyze why it failed
- Gather specific feedback
- Consider revised approach
- Potentially resubmit improved version

## Proposal Examples

### Good Example: Fee Adjustment
> "Reduce transaction fee burn rate from 50% to 40% to increase staking rewards. Analysis shows this maintains deflationary pressure while boosting APY by 0.5%. Simulation data attached."

### Good Example: Grant Request
> "Request 25,000 PYRAX to develop mobile wallet. Milestone 1 (10,000): UI design. Milestone 2 (10,000): Core functionality. Milestone 3 (5,000): Testing and launch. Team: [credentials]. Timeline: 3 months."
